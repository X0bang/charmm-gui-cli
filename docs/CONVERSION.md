# 模拟输入转换与速度验证

## 当前行为

常规建模继续请求官网的格式转换，不自动移除 `run_ffconverter`，也没有启用未经验证的“仅 GROMACS”参数。[官网 Quick Bilayer 文档](https://www.charmm-gui.org/?doc=api&module=quickb)的响应示例包含该字段，但请求参数列表未说明关闭后的产物或单软件选择。网页模块的选择项不能直接当作 API 参数使用。

## 本地转换调查

已用既有归档做离线原型测试，没有提交新的官网任务或修改原模型。使用原归档 `toppar.str` 的加载顺序及 61 个参数文件，记录逐文件 SHA256；未换用另一套网上下载的力场包。软件为 ParmEd 4.3.1、GROMACS 2024.4，归档含 CHARMM36m 蛋白参数和 CGenFF 5.0 参数。

该测试体系含 112229 个原子。直接转换存在两类必要处理：氢质量重分配和溶剂/离子排序。独立复现后，名称、残基名、电荷、质量逐项一致；两套拓扑都通过 `grompp -maxwarn 0`。

最初原型在共同坐标、共同单点设置下失败：LJ-14 相对差异约 328.48%，improper 约 2.86%，总势能约 5.55%。进一步显式使用原参数的 1–4 LJ 定义、修正 improper 的有序通配匹配并重建导出类型索引后，该体系的 11 个单点能量项均达到小于 0.01% 的相对差异门槛；最大差异约 0.0000923%，总势能约 0.00000624%。

### 混合膜的第二个体系

另对已取得最终归档并通过验收的 370471 原子、POPC/POPE 混合膜体系做离线测试，使用它自己的 59 个有序原始参数文件及逐文件哈希，没有借用原版 GROMACS 键参数修正候选。此前“只把水移到末尾”的排序规则在此失败：名称、电荷和质量分别有 128138、86749、72594 项错配，失败记录保留，没有对错误排序的拓扑套用参考坐标并宣称能量通过。

改为从 PSF 的键连接识别完整分子、按首次出现的分子种类稳定分组且水在末尾后，370471 个原子的名称、类型、电荷和质量逐项一致。保留原子映射；独立转换及写出约 124 秒。这只是本地转换测量，不包含官网建模、排队、归档或下载时间。

共同坐标的无约束单点测试有 11 个能量项，最大相对差异约 0.0000573%。编译后的键、Urey–Bradley 角、proper/improper、约束、SETTLE、排除项、45×45 非键参数矩阵及显式 1–4 参数均进行比较，非键系数最大相对差异约 0.000138%，与写出精度有关。比较保留 improper 原子顺序；仅归一化非物理的函数表编号、展示名称及单残基分子模板编号。

CMAP 另从预处理拓扑读取全部六张 24×24 网格，而不是只比较能量或低精度 dump。3456 个网格点在原版的六位小数精度下逐格一致，原始最大差值为 4.8×10⁻⁷ kJ/mol。严格默认容差的失败记录与显式原版精度检查分别保存；比较函数拒绝转置/重排网格、倒转类型、重复记录和非有限数值，并有反例测试。该检查仅证明 CMAP 参数对应，不代表完整转换通过。

### 约束核对

针对上述蛋白、单个非共价配体及 POPC/POPE，独立生成的符号化位置/二面角约束与官网输出逐行核对一致。包括蛋白的 2544 个重原子、配体 40 个重原子、每个脂质的磷原子 z 约束和两条二面角约束；不能推广成已覆盖所有脂质、金属或特殊组分。

读取官网七个最小化/平衡阶段的约束宏，在共同单点设置下分别测试，各 13 个能量项均小于 0.01%，最大约 0.0000764%。为使位置约束能量非零，测试帧相对同一参考帧平移，最高力常数时位置/二面角约束能量分别约 2940.253/1940.719 kJ/mol，两套结果一致。只使用阶段力常数做零步/单帧重算，没有执行这些平衡阶段或生产 MD，也尚未交付通用的独立 MDP 模板生成器。

本机自定义 GROMACS 在启动时会自行绑到不能被调度的 vCPU；原尝试停在读取 TPR 之前，日志保留。上述重算对两套输入使用相同的诊断性 CPU 亲和限制，只限制这个离线进程，不改数值程序或系统设置；不是已验证的跨平台生产运行方案。

原型没有接入常规建模，也未作为可用模型交付。第一个 112229 原子体系仍仅完成无约束单帧能量检查；更多组成、不同坐标帧、通用约束/模板、实际不运行官网转换时的产物和端到端速度均待验收。

这也是为什么不能以“能写出 top”或“能编译 TPR”替代力场等价验证。ParmEd 的 [CHARMM 读取](https://parmed.github.io/ParmEd/html/charmm.html)和 [GROMACS 写出](https://parmed.github.io/ParmEd/html/gromacs.html)接口只是转换基础，不自动证明每个参数、特殊非键项及约束都保持等价。

## 启用门槛

本地转换接入正式流程前，须逐项提供证据：

- 原子顺序/映射、电荷、质量、键/角/二面角、CMAP、NBFIX 和 1–4 参数对应；
- 位置约束和二面角约束及各平衡阶段的参数与官网输出一致；
- 共同坐标下，各单点能量项相对差异小于 0.01%，并明确近零能量的绝对容差；
- 记录原始参数文件哈希、转换器与 GROMACS 版本、有效 mdp 和编译/能量证据；
- 核实“不运行官网转换”时实际返回完整 PSF/CRD/参数及可恢复的归档，并记录体积和端到端耗时。

后一个官网实验尚待用户确认，不能据本地耗时声称已将完整建模缩短到 15 分钟。有限模板的约束单点检查不代表通用迁移或生产模拟适用性。

## 等待与下载

归档压缩的下载 GET 采用 20、30、45、60、90、120 秒的渐进间隔，之后最多每 120 秒查询；如果服务器要求更长的 `Retry-After`，遵守更长时间。重试次数和下一次时间保存到原任务，恢复不会提前查询或重发 POST；旧任务已保存的重试时间继续有效。

前台进度、后台 `jobs watch` 和状态快照显示已接收/总字节数；服务器未给出可靠总量时显示“总量未知”。`Content-Encoding` 导致传输长度与解码后数据不同的情况，不显示误导的总量。现代任务的失败响应及规范化暂存放入 `.charmm-gui/downloads/`，成功后仅清理本次已验证的临时文件，正式压缩包仍只有一份。
